# Project CardSurvival — 현재 개발 현황

갱신: 2026-09-15. 현재 작업 기준은 **`Assets/Scripts/Runtime` + `Assets/Scenes/GameScene.unity`**다.

이 문서의 구현 현황은 소스·씬·프리팹·데이터를 대조한 결과이며, 이번 갱신에서 Unity 플레이·빌드·성능 테스트는 실행하지 않았다. 과거 `Scripts/CardSurvival` 프로토타입의 완료·검증 기록은 아래에 보존하되 현재 Runtime의 완료 상태로 해석하지 않는다.

## 현재 씬 실행과 조작

1. Unity **6000.4.0f1**에서 `Assets/Scenes/GameScene.unity`를 직접 열어 Play한다.
2. 카메라는 마우스 휠 확대·축소, 좌클릭 드래그 이동을 지원한다. Runtime 카메라에는 WASD 이동이나 성 클릭 자동 확대가 없다.
3. `PopupOpener`가 붙은 시설·게시판에 마우스를 올리면 윤곽선을 표시하고, 좌클릭을 놓으면 연결된 팝업을 연다. 현재 전체 팝업 중 하나만 표시한다.
4. 테크 노드를 클릭하면 선택 테두리와 이름·설명·비용을 표시한다. 같은 노드를 다시 클릭하면 선택을 해제한다. 연구 구매와 효과 적용은 아직 없다.
5. 마법 카드를 손패 밖으로 드래그하면 범위 미리보기를 표시하고, 놓으면 효과를 생성하고 카드를 제거한다. 손패 안에서 놓으면 시전을 취소한다.
6. 길드의 현재 샘플 의뢰는 영웅을 즉시 생성한다. 등급 추첨·대기 시간·비용 차감·완료 카드 지급은 아직 없다.

`EditorBuildSettings.asset`에는 현재 `Prototype.unity`와 `SampleScene.unity`가 등록되어 있고 `GameScene.unity`는 등록되어 있지 않다. 현재 씬 목록에는 `SampleScene.unity` 파일이 확인되지 않았다. 기존 빌드 설정/빌드 결과를 Runtime 실행 결과로 간주하지 않는다.

## 최근 반영된 변경

- `UnitCombat`: `공격 주기 = 1 / AtkSpeed`, `선딜 = 주기 × attackTiming`, `후딜 = 주기 × (1 - attackTiming)`으로 계산한다. `AtkSpeed` 단위는 초당 공격 횟수다.
- 타격 시 타겟이 사라졌으면 `Execute`만 건너뛴다. 정상 대기 흐름에서는 `ApplyAttack`과 후딜, `EndAttack`을 계속 진행하여 칼만 들었다가 즉시 Idle로 돌아가던 경로를 수정했다. 플레이 재검증은 별도다.
- `PopupOpener`: 시설/게시판의 포인터 피드백·팝업 열기 분리. `FacilityController`와 `RequestBoard`의 기존 클릭 코드는 제거된 상태다.
- `TechTreePopupView`: 단일 선택·재클릭 해제·정보 표시를 관리하고, `TechNodeView`는 클릭 전달과 테두리 표현을 담당한다.
- `DamageCalculator.Calculate(atkPower, defPower)`는 `Clamp(atkPower - defPower, 0, 100)`으로 작성되어 있다. **현재 피격 경로에서 호출되지 않아 실제 방어력은 아직 적용되지 않는다.**

| 조정 대상 | 현재 위치 |

| 범위·팀·피해/회복 값·수명·틱 간격 | `AreaEffect` 및 파생 컴포넌트 |
| 적 생성량·주기·병종 가중치 | `Assets/Datas/SpawnTable` 및 씬의 `EnemySpawner.TestSpawnTable` 연결 |

현재 샘플: 병사 HP 2/공격력 1/방어력 3/공속 1, 사이클롭스 HP 50/공격력 5/방어력 10/공속 0.2. 병사 타이밍은 0.663이다. 모두 밸런스 확정값이 아니며, 방어력 연결 전후 전투 결과가 크게 달라질 수 있다.

## 확인된 제한과 다음 작업

- 공격 속도 0 이하를 막는 입력/실행 검사가 아직 없다. `1 / 0 → Infinity`, 여기에 타이밍 0을 곱하면 `NaN`이 되어 `TimeSpan` 예외가 난다.
- `CancelAttack()`은 비어 있다. 공격자 사망/비활성화 시 비동기 대기 취소, 시작 시 타겟 검증, 중복 사망/보상 방지는 남은 작업이다.
- 팝업은 현재 `PopupOpener → PopupUI.Open()` 경로다. 씬에 `PopupManager`는 있으나 그룹 관리가 없고, `PopupUI.currentPopup`과 별도 현재 창 필드를 가진다. 시설창과 유닛정보창 동시 표시는 **향후 계획**이다.
- 일부 테크 팝업은 씬의 `nodeInfoRoot`가 미할당이다. 샘플 노드 에셋 2개는 저장 파일상 `m_Script: {fileID: 0}`, `effects: []`이므로 Inspector에서 에셋 인식/참조 확인이 필요하다. 이번 문서 작업에서는 에셋을 수정하지 않았다.
- 적/영웅 생성 목록에 사망 시 제거 흐름이 없고, 적 스폰의 `MaxAlive`도 적용되지 않는다.
- 대규모 병력에서는 AI 탐색, 개체별 물리 동기화와 겹침 보정을 먼저 측정한다. 이번에 성능 병목으로 확정하거나 최적화하지 않았다.

다음 설계 논점은 적의 성 공격 중 타겟 전환 규칙과 포위 시 아군 출전 처리다. 이후 공격 취소·피해 규칙·연구 효과를 순차적으로 연결한다. 매판 군단이 달라지는 아이디어와 맵/반복 플레이 확장은 장기 보류 항목이며 현재 작업 범위를 늘리지 않는다.

# 과거 프로토타입 기록 — PAPERKEEP

> 아래는 기존 README 원문이다. `Scripts/CardSurvival` / `Prototype.unity`에 대한 당시 기록이며 현재 `Scripts/Runtime` 구현·조작·수치·검증 결과가 아니다. 과거 빌드는 이번에 재검증하지 않았다.

# PAPERKEEP · 종이 성채

Unity 6000.4.0f1 / 2D URP / Input System / 한국어 UI로 만든 플레이 가능한 카드 디펜스 프로토타입입니다. 원본 `SampleScene`과 사용자가 작성한 `Assets/Scripts/Scripts.cs`는 보존했습니다.

## 실행

1. `Assets/Scenes/Prototype.unity`를 열고 Play를 누릅니다.
2. 성을 클릭하거나 휠로 확대합니다. 성의 왼쪽은 군, 아래는 길드, 오른쪽은 마법 시설입니다.
3. 길드를 한 번 클릭하여 D~S급 영웅을 의뢰합니다. 초기 자금으로 D급 영웅 또는 파티를 의뢰할 수 있습니다.
4. 마법 카드는 10초마다 자동으로 도착합니다. 초반부터 의뢰와 마법을 사용해 전선을 유지하세요.

macOS 개발 빌드: `Builds/Paperkeep.app`. 이 환경에는 Mac 빌드 모듈만 설치되어 있어 Windows 실행 파일은 생성하지 않았습니다. 프로젝트 코드는 PC 키보드·마우스 입력을 사용합니다.

`Tools > Card Survival > Create Prototype`은 기본 데이터, 루트 프리팹, 씬이 없는 경우 생성합니다. 이미 생성한 콘텐츠를 덮어쓰지 않습니다. `Build macOS` 메뉴로 다시 빌드할 수 있습니다.

## 조작

| 동작 | 조작 |
|---|---|
| 카메라 확대·축소 | 마우스 휠 |
| 카메라 이동 | WASD 또는 마우스 좌클릭 드래그 |
| 성으로 이동·확대 | 성 클릭 또는 오른쪽 아래 `성 살펴보기` |

일시정지 중에는 전투·생산·카메라·게임플레이 조작이 멈춥니다. 시설 팝업만 여는 경우 전투는 계속됩니다. 증강 선택 중에는 증강 선택만 가능합니다. 카드를 버리거나 판매할 수 없으며 완성 카드는 공용 덱에 쌓이고 빈 손패를 자동 보충합니다.

## 구현된 게임 흐름

- 근접병은 4초마다 자동생산합니다. 원거리 진입 연구 후부터 궁수를 독립적으로 6초마다 생산합니다. 인구가 가득 차면 완료 상태로 기다리며 병력이 줄면 보충합니다.
- 영웅은 D·C·B·A·S 5등급입니다. 각 등급에 근접 기사 리아/원거리 사냥꾼 로웬이 있고 의뢰 시 해당 등급에서 무작위 선정합니다. 대기 의뢰만 취소·환불할 수 있습니다.
- 파티는 전위 1명과 궁수 2명입니다. 파티 진입 연구로 궁수 1명이 회복사로 바뀝니다. 같은 파티는 표적과 이동 방향을 공유합니다.
- 마법은 불꽃 폭발/생명의 정원을 번갈아 자동 지급합니다. 공격/지원 테크가 실제 피해·지대·연쇄·보호막·회복·기절에 적용됩니다.
- 지휘 경험치 → 시설 투자 → 시설 전용 기술 포인트로 성장합니다. 6루트, 48노드, 시설별 종결 1개 제한을 적용했습니다.
- 고블린·오크가 사방에서 공격하고, 사이클롭스 처치마다 증강 선택 기회를 받습니다. 시간 경과만으로 증강을 주지 않습니다.
- 12개 증강, 30분 생존 승리, 성 파괴 패배, 결과 화면, 재시작을 연결했습니다.
- 유닛/투사체/효과 풀, 세대 번호가 있는 개체 참조, 공간 그리드 탐색을 사용합니다. 투사체 표시 풀이 가득 차도 피해 판정은 유지합니다.

런타임 상태는 설계 에셋과 분리되어 있어 플레이·재시작이 원본 데이터에 누적되지 않습니다. 시설/증강 효과의 처리 로직은 `BattleSimulation`에 있으며, 효과 이름과 수치 설명만 바꿔 새 효과 종류가 생기지는 않습니다.

일반 적 초당 생성량은 0·5·10·20·25·30분에 각각 **1·2·3·6·8·12마리**를 기준으로 보간합니다. 기존 40마리/초 기본안은 새 마법 공급/영웅 의뢰 규칙의 자동 운영 점검에서 조기 패배가 반복되어 줄였습니다. 후반 물량과 체력·공격력 증가는 유지합니다.

보스는 2·5·8·11·14·17·20·23·26분에 등장합니다. 첫 보스의 기본 체력은 1,800, 공격 피해 45이며 후속 보스의 체력이 증가합니다. 보스 공격은 기본 근접 공격이며 복잡한 전용 패턴은 없습니다. 보스는 즉사 효과의 대상에서 제외합니다.

## 아트

`Assets/Resources/CardSurvival/Art`에 내장 imagegen 도구로 생성한 PNG 13종을 저장했습니다. 스택랜드 느낌의 굵은 선, 차분한 색, 종이 질감을 사용한 독자적인 성·시설·인물·몬스터·마법 일러스트입니다. 전장 유닛도 직사각형 종이 카드로 표현하며 캐릭터 애니메이션은 없습니다. 카드 프레임·범위 표시·보드 도형은 코드로 그립니다.

정확한 생성 프롬프트는 [ArtPrompts.md](ArtPrompts.md)에 기록했습니다. 한글 폰트는 Noto Sans CJK KR이며 `Assets/Resources/CardSurvival/Fonts/OFL.txt`에 라이선스를 포함했습니다.

## 개발 및 검증 도구

- Editor/Development Build에서 F1: 개발 정보, F2: 골드/XP, F3: 보스 출현, F4: 1배/5배속입니다.
- `Tools > Card Survival > Run EditMode Tests`로 핵심 규칙을 점검합니다. PlayMode 테스트는 Unity Test Runner에서 `CardSurvival.PlayTests`를 실행합니다.
- `Tools > Card Survival > Audit Six Builds`는 여섯 투자 경로를 가속 논리 시뮬레이션으로 진행하며 `Artifacts/six-build-audit.csv`에 결과를 저장합니다. 자원 지급이나 성 무적을 쓰지 않습니다. 실제 30분 수동 플레이를 대신하지 않습니다.
- `DevelopmentAudit`의 `--autoplay-audit`, `--quick-audit`, `--stress-audit`는 별도 실행 검증용 개발 빌드 옵션입니다. `--audit-output=<경로>`로 보고서 위치를 지정합니다. 스트레스 모드는 개체 수를 유지하려고 높은 체력과 성 보호를 사용하므로 정상 게임 밸런스 검증과 구분합니다.

검증 결과와 실행하지 못한 항목은 루트 README 및 `Artifacts` 보고서를 참고하세요.
