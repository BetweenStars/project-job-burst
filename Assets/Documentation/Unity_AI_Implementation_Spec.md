# 현재 Runtime 구현 기준 / 후속 설계 기록

갱신: 2026-09-15. 기준 경로: `Assets/Scripts/Runtime`, `Assets/Scenes/GameScene.unity`, `Assets/Prefabs`, `Assets/Datas`.

## 문서 적용 순서

1. 현재 사용자의 작업 요청과 확정한 변경을 우선한다.
2. 이 문서 앞부분의 **현재 구현**과 [README](README.md)를 현황 기준으로 사용한다.
3. **후속 방향 / 미정 / 보류**는 구현 완료도, 즉시 구현하라는 지시도 아니다.
4. 뒤쪽의 과거 명세 원문은 보존용 참고다. 당시의 “구현하라”, “확정”, “반드시 포함”을 현재 작업의 자동 승인이나 완료 상태로 해석하지 않는다.

기존 문서는 `Scripts/CardSurvival`의 별도 프로토타입을 위한 대규모 완성 명세였다. 현재는 컴포넌트 기반 Runtime을 단계적으로 개발한다. 옛 서비스 이름·48노드·12증강·고정 스폰 일정·수치를 새 구현에 일괄 이식하지 않는다. 기존 기획 중 최근에 재논의하지 않은 항목을 임의로 폐기하지도 않는다.

## 전투 실행 순서 — 사용자 확정 기준

확정일: 2026-09-18. SoA 저장소와 Jobs·Burst를 사용하는 전투 구조의 실행 순서다. 아래는 구현 목표이며, 모든 단계가 현재 코드에 구현되었다는 뜻은 아니다. 실행 순서는 아래의 2026-09-15 구현 기록 및 과거 명세보다 이 기준을 우선한다.

사용자가 전투 실행 순서를 물으면 다음 블록의 단계 이름과 순서를 그대로 안내한다. 사용자가 명시적으로 변경을 요청하기 전에는 단계를 임의로 생략·재배열·변경하지 않는다. 변경을 확정하면 이 블록도 함께 갱신한다.


## 2. 공격 주기와 모션

### 현재 구현

- `AtkSpeed`는 **초당 공격 횟수**이며 `float`다. HP/공격력/방어력은 `int`, 이동속도/사거리도 `float`다.
- `attackInterval = 1f / AtkSpeed`.
- 선딜은 `attackInterval * attackTiming`, 후딜은 `attackInterval * (1f - attackTiming)`초다. `TimeSpan.FromSeconds`로 `UniTask.Delay`에 전달한다.
- `attackTiming`은 `UnitCombat`의 0~1 Inspector 슬라이더다. 공격 시작 시 주기를 계산하므로 진행 중 공속 변경은 다음 공격부터 반영된다.
- `StartAttack → 선딜 → 타겟이 남아 있으면 Execute → ApplyAttack → 후딜 → EndAttack` 순서다.
- 이전의 `if (target == null) return`은 제거됐다. 타겟 소멸 시 공격 실행만 생략하고 타격 모션/후딜을 유지하는 임시 수정이 반영됐다.
- 이 임시 수정은 근접/투사체/범위 공격에 공통이다. 타겟이 없으면 현재 투사체와 장판도 생성하지 않는다.
- 병사 프리팹은 세 이벤트가 스프라이트 메서드에 연결되어 있다. 사용자가 실제 모션을 작업한 병종은 현재 병사다. 전체 병종의 애니메이션 완료로 기록하지 않는다.

### 후속 방향 — 미구현

- 타겟 소멸과 공격자 자체의 중단을 구분한다. 타겟 소멸로 전체 모션을 취소하지 않는다.
- 근접은 타격 시점의 유효성에 따라 헛스윙, 투사체는 저장한 위치/방향으로 발사, 장판은 공격 시작 시 생성하여 자체 딜레이로 타격하는 방식을 논의했다. 위치/방향 저장, 사거리 재검사와 세부 발동 시점은 아직 구현하지 않았다.
- 공격자 사망·비활성화 등의 취소에 공격별 CancellationTokenSource를 쓰는 방식을 논의했다. `CancelAttack`은 여전히 비어 있다.
- `CanAttack + Attack` 대신 `TryAttack`을 두는 방식을 검토했다. 현재 호출 방식은 그대로다. 실패가 사거리 밖인지, 공격 중/기절인지 구분하여 AI가 이동 여부를 정해야 한다.
- 공속 양수 검사는 아직 없다. Inspector 제한과 실행 전 검사가 필요하며, 0 이하를 임의의 아주 작은 양수로 바꿔 긴 공격을 시작시키지 않는 방향을 추천했다.
- 타겟 null, 공격자 수명, 중복 사망·보상 방지는 미완료다. `finally`는 예외에도 종료 이벤트를 호출하므로 모션 유지 수정이 모든 중단 원인을 해결한 것은 아니다.

## 3. 피해·능력·연구 효과

### 현재 구현

- 낮은 정수 체력·공격력·방어력을 사용하는 방향으로 데이터를 조정 중이다. “일반 체력 5~6, 보스 50”은 규모의 예시이며 모든 유닛의 확정 체력이 아니다.
- `DamageCalculator`는 고정 차감 후 0~100 제한을 반환한다. 100 상한은 현재 코드값이며 밸런스 확정 규칙은 아니다.
- `UnitCombat.CalculateDamage`는 공격력만 반환하고, `UnitController.TakeDamage`는 받은 정수를 그대로 차감한다. 방어력 계산기는 아직 연결되지 않았다.
- 투사체 클래스에는 이동만 있고 충돌·피해 적용·수명 종료는 없다. 범위 효과에는 팀 필터와 반복/일회 피해·회복이 있다.
- `TechNode`는 ScriptableObject이며 ID/표시명/설명/비용/효과 목록/단일 부모를 저장한다. `TechEffect`는 종류/대상 ID/정수 값을 저장한다.
- 효과 종류는 유닛 해금, 공격력 증가, 최대 HP 증가다. 구매와 실제 적용은 비어 있다. 샘플 에셋의 효과 목록도 비어 있다.
- `BaseAbillity`와 보호 오라는 미구현이다. Context, 버프 관리자, 화상/독도 없다. 현재 파일/폴더 철자는 `Abillity`이며 이번 문서 작업에서 이름을 변경하지 않았다.

### 논의한 설계 방향 — 미구현

- 연구 결과를 런타임 Context에 해금/보너스로 저장하고, 생산 시 원본 스탯 + Context 보너스로 초기화한다. 유닛은 UI 노드를 직접 조회하지 않는다.
- 보호 오라는 별도 능력으로 두고, 범위 안 아군에 피해 감소/방어 보너스를 등록·해제한다. 피격자가 현재 방어·버프를 모아 공통 계산기에 전달하고 체력을 반영한다.
- 화상·독은 유닛의 상태 효과 관리에서 지속시간·틱·중첩을 관리한다. 장판은 공간에 남고 상태 효과는 대상에 붙는다는 차이가 있다.
- 고정 방어력은 매 타격/틱마다 차감할 경우 연타·작은 틱 피해에 강해진다. 피해 종류별 방어 적용, 최소 피해, 중첩, 퍼센트 도입 여부는 미확정이다.
- 이미 생성된 유닛에 연구를 소급할지, 최대 HP 증가 시 현재 HP를 어떻게 바꿀지는 새 Runtime 기준으로 확정하지 않았다. 과거 명세의 비율 보존 규칙을 자동 적용하지 않는다.
- 공격 타이밍과 유닛별 밀림 가중치를 `UnitData`에 모으는 것은 제안 상태다. 현재는 컴포넌트에 있으며, 겹침 보정의 기술적 반응/속도 설정과 유닛 특성을 구분한다.

## 4. 팝업·테크 선택

### 현재 구현

- `WorldPointer → PopupOpener.OnClick → targetPopup.Open`이며, `PopupOpener`는 대상 UI를 직접 저장한다. 클릭용 UnityEvent 방식으로 바꾸지 않았다.
- `PopupUI.currentPopup`이 전체 단일 팝업을 관리한다. 같은 창을 다시 열면 유지하고 다른 창은 기존 창을 닫는다. 닫기 버튼은 `PopupUI.Close`에 연결한다.
- `PopupManager.OpenPopup`에는 별도의 현재 창과 재클릭 토글 구현이 있다. 현재 Opener는 이를 호출하지 않고, 씬/프리팹의 `OpenPopup` 이벤트 연결도 확인되지 않았다. 두 관리 방식이 통합 완료된 상태가 아니다.
- 노드 선택은 팝업이 결정하고, 노드 뷰는 클릭 요청/테두리 표시만 담당한다. 연구 완료 상태와 UI 선택 상태는 다르다.

### 향후 계획 — 사용자 확인

- 시설 팝업은 오른쪽 세로 영역, 유닛 정보창은 왼쪽 아래 영역에 표시하여 동시에 열 수 있게 한다.
- 의뢰/테크트리/시설 기능창은 시설 그룹으로, 유닛 정보는 별도 그룹으로 관리하는 방향이다. 각 그룹 안에서는 하나만 열린다. 시설 창들끼리도 동시에 열 필요가 생기면 추가 분류를 결정한다.
- 매니저가 그룹별 열린 창의 단일 관리자가 되도록 정리한다. 대상 UI 직접 참조는 유지할 수 있다. 그룹 enum/딕셔너리와 유닛정보 UI는 아직 없다.

## 5. 적 행동·출전·매판 변화

### 현재 동작

- 적은 주변 아군을 탐색하고 있으면 접근/공격, 없으면 성에 접근/공격한다. 공격 중에는 재탐색하지 않는다.
- 아군은 주변 적/중립을 탐색하여 접근/공격한다. 타겟이 없을 때 성을 참조하지만 실제 복귀 이동은 TODO다.
- 군은 지정한 네 위치에서 분대를 생성한다. 포위 상태에서 빈 출전 위치를 찾거나 안전 공간을 확보하는 로직은 없다.
- 스폰은 연결된 TestSpawnTable 기반이다. 군단별 선택, 별도 보스 시간표, MaxAlive 제한은 아직 없다.

### 미정

- 성을 공격 중인 적이 주변에 새 아군이 나오면 전환할지, 성 공격을 유지할지.
- 도시가 완전히 포위된 상황에서 아군을 밀어내며 출전시킬지, 내부/생산 완료 상태로 대기시킬지. 어느 제안도 확정하지 않았다.
- “안전한 소환 링에서 항상 등장”이라는 과거 문구는 현재 출전 공간을 보장하지 않는다.

### 장기 보류

- 사용자가 말한 랜덤 이벤트는 선택형 보상이 아니라 **이번 판에 등장하는 군단이 달라지는 방식**이다. “4명의 군단장 중 한 군단”은 예시이며 군단 수/편성/공개 시점은 미정이다.
- 군단 정체성 안에서 세부 편성을 바꾸는 것은 제안이며 확정 요구사항이 아니다.
- 반복 플레이 확장, 추가 맵, 랜덤 이벤트의 구체화는 나중에 검토한다. 과거 보스 처치 증강의 유지/삭제도 이번 논의만으로 결정하지 않는다.

## 6. 검토 결과와 다음 작업 후보

1. 적 타겟 전환과 출전 규칙을 먼저 결정한다.
2. 공격자 사망/비활성화 취소와 타겟 검증, 공격 속도 입력 검사를 정리한다.
3. 최종 피해 계산을 피격 경로에 연결하고 저수치 밸런스를 점검한다.
4. 테크 구매와 Context, 해금/스탯/능력 적용을 순차 연결한다.
5. 팝업 그룹, 이동/겹침 보정 책임과 대량 유닛 성능은 필요한 시점에 정리한다.

점검이 필요한 현재 데이터: 일부 팝업 `nodeInfoRoot` 미할당, 테크 샘플 에셋 `m_Script` 참조 0/빈 효과 목록, GameScene 미등록 및 존재하지 않는 SampleScene을 가리키는 기존 빌드 설정. 이는 소스/직렬화 파일 기준으로 발견했으며 이번에는 수정하지 않았다.

문서 검증 범위는 코드·씬·에셋 대조와 문서 링크/기록 보존 확인이다. 기존 프로토타입 테스트는 새 Runtime의 테스트가 아니다. 이후 코드 변경 시 공격 중 타겟 소멸, 공격자 사망, 공속 0, 팝업 그룹 독립성, 연구 중복 적용을 해당 기능 범위에서 검증한다.

# Unity AI 코딩 에이전트용 게임 구현 프롬프트 / 명세

> 이 파일 전체를 Unity 프로젝트에 접근 가능한 AI 코딩 에이전트에게 전달한다. 에이전트는 아래 지시대로 프로젝트 조사, 구현, 콘텐츠 생성, 검증까지 수행한다. 이 문서는 기획 문서이면서 실제 작업 지시서다.

## 0. 에이전트에게 내리는 작업 지시

당신은 Unity 게임플레이와 성능 최적화에 숙련된 개발자다. 아래 명세에 따라 **플레이 가능한 2D 탑다운 실시간 생산 운영형 카드 디펜스 프로토타입**을 구현하라. 설명이나 빈 클래스만 제출하지 말고, 씬·프리팹·데이터·UI를 연결하여 시작부터 승리/패배와 재시작까지 작동하게 만들어라.

1. 먼저 프로젝트의 `AGENTS.md`, `ProjectSettings/ProjectVersion.txt`, `Packages/manifest.json`, 기존 씬·입력·UI·렌더 파이프라인·테스트 구조를 확인한다.
2. 기존 프로젝트의 Unity 버전과 패키지, 코드 스타일을 유지한다. 버전 업그레이드, 렌더 파이프라인 교체, 유료 에셋 구매를 임의로 진행하지 않는다.
3. 프로젝트가 없다면 설치된 Unity Editor 중 사용 가능한 버전으로 2D 프로젝트를 만든다. Editor가 없다면 버전을 추측해 실행 성공을 주장하지 말고, 생성 가능한 소스와 정확한 수동 설정 절차를 제공한다.
4. 명시적으로 확정된 기획을 우선한다. 미정 세부사항은 이 문서의 **구현용 기본값**으로 진행하고, 변경한 가정은 README에 남긴다.
5. 직접 생성한 스택랜드풍 손그림 아트를 직사각형 카드에 사용한다. 캐릭터 애니메이션은 만들지 않아도 되며 이동·투사체·범위 피드백은 유지한다. 데이터와 표현을 분리하여 아트를 교체할 수 있게 한다.
6. 각 단계가 끝날 때 컴파일과 해당 기능을 확인한다. 테스트를 통과시키기 위해 기능이나 검증을 제거하지 않는다.
7. 마지막에는 실행 방법, 주요 파일, 구현 기능, 테스트 결과, 성능 측정 조건, 남은 문제를 보고한다. 실행하지 못한 항목은 명확히 구분한다.

### 요구사항의 우선순위

- **확정 기획:** 1절의 항목. 임의로 삭제하거나 다른 장르의 기능으로 바꾸지 않는다.
- **구현용 기본값:** 수치, 구체적인 노드 이름과 효과, 경험치 배분, 상한, 조작 세부, 적 구성. 추가 질문 없이 프로토타입을 완성하기 위한 제안이며 튜닝 가능하게 만든다.
- 과거 대화의 마석/플러그인 장착, 군 유닛 카드, 출격 방향 수동 지정은 현재 구현에 포함하지 않는다.
- 외부 대화나 파일을 다시 읽지 않아도 이 파일만으로 작업할 수 있어야 한다.

`군이 자동으로 전선을 유지 → 적 처치로 골드/경험치 획득 → 시설 성장 및 영웅 의뢰 → 의뢰 완료 영웅 카드/주기 지급 마법 카드 획득 → 영웅 투입/마법 사용 → 사이클롭스 처치 후 증강 선택 → 더 큰 적 물량에 대응`

## 2. MVP 범위와 완료 기준

### 최종 MVP에 반드시 포함

- 단일 전장, 중앙 성 1개, 논리적 시설 3개, 30분 승리/성 파괴 패배/재시작.
- 군 근접병·궁수 자동생산과 자동전투.
- 등급별 영웅 의뢰와 완료 카드 지급, 기존 파티 카드 의뢰, 공격/지원 마법 카드의 주기적 자동 지급.
- 시설 투자와 레벨업, **6개 루트 전체의 내부 분기와 실제 효과**.
- 랜덤 증강 최소 12종, 3개 중 1개 선택, 적용과 선택 UI.
- 손패·큐·범위 미리보기·자원·시설/트리 UI·종료 요약.
- 고블린·오크 일반 적과 사이클롭스 보스, 후반 혼합 물량 증가와 보스 처치 증강 보상.
- 풀링, 공간 기반 탐색, 스트레스 테스트와 기본 성능 계측.
- 임시 그래픽이어도 전투 역할과 마법 범위가 구별될 것.

### 첫 수직 슬라이스에서만 줄여도 되는 범위

첫 검증은 3분, 적 1종, 군 근접병 1종, 모험가 1종, 공격 마법 1종으로 진행한다. 이는 중간 작업 단계다. 최종 제출 시 6루트·성장·증강·30분 모드를 복원하여 완성한다.

### MVP 제외

멀티플레이, 직접 조작하는 플레이어 캐릭터, RTS 부대 선택/이동 명령, 건물 자유 배치, 공장/자원 운송, 덱 셔플·수동 드로우(생산 카드 보관 덱과 손패 자동 보충은 포함), 마나, 장비/인벤토리, 영구 성장, 저장 중단 후 이어하기, 다중 맵, 복잡한 다단계 보스 전용 패턴(사이클롭스 보스와 처치 보상은 포함), 유료 에셋, 과도한 프레임워크. 이들은 현재 구현을 막는 의존성이 되어서는 안 된다.

## 3. 전장과 자동전투 기본값

- 직교 카메라와 XY 평면을 사용한다. 기본 배율에서 중앙 성과 주요 전선을 파악할 수 있게 하고, 마우스 휠로 확대·축소하며 WASD 또는 마우스 좌클릭 드래그로 카메라를 이동한다. 확대 배율과 이동 범위에는 데이터로 조절 가능한 제한을 둔다.
- 마을/성은 동일한 방어 목표다. 성을 확대하면 내부의 군·모험가 길드·마법사 협회가 보이고, 각 시설을 더블클릭하면 해당 시설 테크트리 팝업을 연다. 시설은 논리적 시스템을 표현하며 별도 피격 대상이 아니다.
- 카메라 드래그와 클릭/더블클릭을 구분한다. 드래그를 끝내도 시설 선택이나 마법 시전이 발생하지 않으며, UI 위에서 시작한 입력은 카메라 조작으로 전달하지 않는다. 마법 조준 중에도 드래그는 카메라 이동, 드래그 없는 유효 지점 클릭은 시전으로 처리한다. 드래그 판정 거리, 더블클릭 간격, 시설 표시 배율은 구현용 기본값으로 조절 가능하게 둔다.
- 시설은 안전한 마을 내부의 논리적 시스템이다. 시설용 체력, 피격 판정, 수리, 별도 방어 AI를 만들지 않는다.
- 적은 북/동/남/서 외곽 구간에 분산 생성하며 성을 향해 이동한다. 각 구간 가중치와 위치 흔들림은 데이터로 설정한다.
- 적은 가까운 아군이 교전 범위 안에 있으면 공격하고, 그렇지 않으면 성으로 진군한다. 성 주변 공격 반경에 들어오면 성을 공격한다.
- 아군은 주변 적을 자동 탐색한다. 적이 없으면 성 주변 방어 반경으로 복귀하고, 추격 한계를 넘어 외곽까지 쫓아가지 않는다.
- 군/모험가 모두 성 주변의 안전한 소환 링에서 등장한다. 모험가 사용에 좌표나 방향 입력을 요구하지 않는다.
- 유닛 상태는 `Idle / Move / Attack / Dead`로 시작한다. 공격마다 유효 대상·거리·생존 여부를 다시 확인한다.
- 원거리는 사거리 안에서 공격하고 사거리 밖에서 접근한다. 초기 MVP에 복잡한 후퇴 AI는 필요 없다.
- 장애물 없는 전장과 부드러운 분리 이동을 사용한다. 복잡한 길찾기와 유닛끼리의 강체 충돌은 기본 구현에 넣지 않는다.
- 군 기본 상한 80명, 모험가 상한 12명. 파티 카드는 구성원 전부가 들어갈 공간이 있어야 사용할 수 있다.
- 전투 능력치·공격 간격·탐색 범위·추격 범위·소환 간격·유닛 상한은 모두 데이터로 조절한다.

## 4. 자원, 경험치, 시설 성장

### 4.1 경험치 규칙의 해석

과거에 시설 사용 경험치가 논의되었지만 이후에는 **적 처치 경험치로 레벨업하고 원하는 시설에 투자하는 방식**이 제시되었다. MVP는 후자를 우선하여 다음 한 경로로 통일한다. 별도 자동 사용 경험치를 중복 지급하지 않는다.

`적 사망 → 전역 경험치 → 지휘 레벨업 → 시설 투자 포인트 → 선택 시설 경험치 → 시설 레벨업 → 해당 시설 기술 포인트 → 테크 노드 구매`

- 적이 죽으면 처치 주체와 무관하게 전역 골드/경험치를 자동 지급한다. 바닥 아이템 수집 조작은 없다.
- 시작: 골드 150, 지휘 레벨 1, 경험치 0, 투자 포인트 0, 각 시설 레벨 1.
- 지휘 레벨업마다 투자 포인트 1개. 한 번의 보상으로 여러 레벨업이 가능하며 남은 경험치를 이월한다.
- 기본 지휘 최대 레벨 16: 한 판에 획득 가능한 투자 포인트는 총 15개. 이후에도 골드는 지급한다.
- 다음 지휘 레벨 경험치 기본값: `100 + 25 × (현재 지휘 레벨 - 1)`. 15번 레벨업에는 총 4,125 경험치가 필요하다. 적 경험치/스폰을 함께 조정해 정상 플레이에서 후반에 도달하도록 한다.
- 투자 포인트 1개를 선택 시설 경험치 100으로 변환한다. 시설 레벨마다 경험치 100이 필요하고 최대 레벨은 10이다. 만렙 시설에는 투자를 거절한다.
- 시설이 레벨업하면 그 시설 전용 기술 포인트 1개를 지급한다. 경험치 투자 자체와 노드 구매를 구분하고 남은 포인트를 보관한다.
- 시설 사용/기여량은 통계로 기록할 수 있지만 성장 보상으로 환산하지 않는다. 추후 사용 경험치를 추가하려면 별도 설정과 경제 재조정이 필요하다.
- 골드는 길드의 영웅/파티 의뢰에만 사용한다. 군 자동생산, 마법 카드 자동 지급, 카드 사용, 기술 포인트 구매에는 골드를 요구하지 않는다.

### 4.2 성장 예산의 의도

시설 시작 레벨의 합은 3이고 추가 레벨 예산은 15이므로, `군 10 / 길드 6 / 마법 2` 같은 결과가 가능하다. 이는 **한 시설 마스터 + 한 시설 중간 + 한 시설 초반**을 유도하는 기준이다. 정확한 분배를 강제하지 않으며 6/6/6 등의 분산 투자도 허용한다. 두 시설 만렙은 각각 9포인트가 필요하므로 총 예산으로 불가능하다.

초기 세 시설은 기본 기능을 즉시 제공한다. 군은 기본 근접병을 생산하고, 길드는 기본 등급 영웅/파티 의뢰를 제공하며, 마법은 기본 공격/지원 카드를 주기적으로 지급한다. 루트 투자는 해당 계열의 전문화이며 기본 생존 수단 전체를 잠그지 않는다.

## 5. 생산과 카드 상태 전이

### 5.1 군 자동생산

- 군 테크트리는 유지하며 군 생산에는 카드, 골드 결제, 수동 생산 예약, 생산/출격 버튼을 사용하지 않는다. 게임 시작 시 근접병 생산 타이머가 자동으로 작동하고, 기본 4초마다 1명을 생산하여 자동 출격시킨다.
- 원거리 루트 진입 노드를 구매하면 그 시점부터 궁수 생산 타이머가 자동으로 작동하며, 기본 6초마다 1명을 생산하여 자동 출격시킨다. 해금 전 시간은 누적하지 않고 첫 궁수는 해금 후 한 생산 주기가 완료되면 등장한다.
- 근접병과 궁수 생산은 각각 독립된 주기로 계속되며 같은 군 인구 상한을 공유한다. 원거리 해금 후에도 근접병 생산은 유지한다. 4초/6초는 조정 가능한 구현용 기본값이다.
- 타이머 완료 시 인구 여유가 있으면 소환한다. 상한이면 완료 상태에서 대기하고 여유가 생기면 생산 1회만 수행한다. 대기 중 생산 횟수를 무한 적립하지 않는다.
- 여러 라인이 동시에 준비되면 순환 우선순위로 처리하여 특정 라인이 계속 굶지 않게 한다.
- 군 유닛 사망 시 슬롯이 반환된다. 레벨업/테크/증강으로 생산 주기, 수량, 상한, 능력이 바뀐다.

### 5.2 영웅 의뢰와 마법 카드 자동 지급

#### 길드: 등급별 영웅 의뢰

`의뢰 등급 선택 → 조건 검증/골드 결제 → Queued → Producing → 해당 등급 영웅 카드 지급 → Delivered`

- 플레이어가 원하는 영웅 등급으로 의뢰하면 정해진 시간이 지난 뒤 그 등급에 속한 영웅 카드 1장을 지급한다. 다른 등급의 영웅이 나오거나 추가 클릭/결제를 요구하지 않는다.
- 등급은 낮은 순서로 D·C·B·A·S다. 초기 구현에서는 모든 등급 의뢰를 제공하고 비용/시간으로 차등을 둔다. D: 140G/18초, C: 230G/24초, B: 380G/32초, A: 620G/42초, S: 1,000G/55초를 조정 가능한 기본값으로 사용한다. 각 등급에 근접 기사와 원거리 사냥꾼 후보를 제공한다.
- 구현용 기본값: 같은 등급의 후보가 여러 명이면 해당 등급 내에서 균등 추첨한다. 의뢰용 난수는 전투·증강 추첨과 분리하고, 의뢰 등록 시 결과 영웅 ID를 확정해 저장한다. 같은 등급 내 무작위 선정은 확정된 방식이다.
- 기존 골드 결제와 FIFO 의뢰 큐를 유지한다. 큐 기본 용량은 5개, 동시에 1개 진행하며 대기/진행 중 의뢰를 큐 용량에 포함한다. 등급 해금, 후보 존재, 골드, 큐 여유를 모두 검증한 뒤 의뢰와 결제를 한 번에 처리한다.
- 의뢰 등급, 결과 영웅 ID, 지불 비용, 소요시간은 등록 시 저장한다. 이후 비용/시간/해금 변경은 새 의뢰부터 적용한다.
- 완료 카드를 정확히 한 번 덱에 인계하면 의뢰 큐 슬롯을 반환하고 다음 의뢰를 시작한다. 손패가 가득 차도 의뢰 진행을 막지 않는다.
- 아직 시작하지 않은 `Queued` 의뢰만 취소할 수 있고 지불 골드를 전액 환불한다. 진행/완료 의뢰는 취소할 수 없고, 완성 카드는 버리기·판매·환불할 수 없다.
- 기존 파티 카드는 별도 파티 의뢰로 유지한다. 영웅 등급 내 추첨은 영웅 의뢰에 적용하며 파티 구성은 기존 규칙을 따른다.

#### 마법사 협회: 일정 주기마다 1장 지급

`런 시작 → 지급 타이머 진행 → 마법 카드 1장 덱 인계 → 다음 주기 시작`

- 플레이어의 생산 예약과 골드 결제 없이 일정 시간마다 마법 카드 1장을 자동 지급한다. 공격/지원 각각 1장이 아니라 협회 전체에서 주기당 총 1장이다.
- 구현용 기본값: 지급 간격은 10초, 시작 즉시 타이머를 시작하여 첫 카드는 10초 후 지급한다. 공격/지원 기본 카드를 번갈아 지급하며 첫 카드는 공격 마법이다. 간격과 카드 선정 방식은 사용자 확정 전의 잠정안이며 데이터로 조절한다.
- 손패가 가득 차도 덱에 카드를 보관하고 지급 타이머는 계속 작동한다. 의뢰 큐나 수동 취소 기능은 없다.
- 마법 생산속도 테크는 카드 자동 지급 간격에 적용한다. 각 주기 시작 시 간격을 저장하며 진행 중 주기에는 소급 적용하지 않는다.
- 일시정지와 증강 선택 중에는 지급 타이머도 멈춘다. 게임 종료 후에는 지급하지 않고 재시작 시 타이머와 카드 선정 순서를 초기화한다.

#### 공통 카드 인계와 잠정 기본값

- 영웅/파티 의뢰 완료와 마법 자동 지급은 같은 공용 덱으로 인계한다. 카드 흐름은 `덱 → 손패 → 사용`이며 사용 후 덱으로 되돌아가지 않는다.
- 덱은 지급 완료 순서의 FIFO다. 동시 지급은 완료 시각, 시설 ID, 시설별 지급 순번으로 정렬한다. 모든 카드에 고유 지급 ID를 부여해 중복 인계를 방지한다.
- 손패에 여유가 있으면 덱 선두부터 자동 보충한다. 덱에는 게임 규칙상 보관 상한을 두지 않는다. 셔플·임의 선택·순서 변경은 없다.
- 카드 사용에는 추가 골드 비용이 없다. 기존 마법 예약 비용 60G/70G와 개별 생산시간 8초/10초는 폐기하고 협회 공통 지급 주기로 대체한다.

| 카드 ID | 획득 경로 | 잠정 비용/시간 | 기본 효과 |
|---|---|---|---|
| `guild.party.basic` | 기존 파티 의뢰 | 90G / 12초 | 전위 1 + 궁수 2 소환 |
| `guild.hero.0.0` | D등급 영웅 의뢰의 기사 후보 | 140G / 18초 | 높은 체력/공격력의 영웅 1명 소환 |
| `magic.attack.burst` | 협회 주기 지급 | 무료 / 협회 공통 주기 | 지정 원형 범위에 즉시 피해 |
| `magic.support.field` | 협회 주기 지급 | 무료 / 협회 공통 주기 | 지정 원형 범위에 6초 회복장 |

기본 공격 마법은 피해 60/반경 3, 회복장은 초당 아군 최대 체력 5% 회복/반경 3으로 시작한다. 성은 회복 대상에서 제외한다. 각 카드의 지속시간과 수치는 밸런스 데이터다.

### 5.3 덱, 손패와 사용

- 손패 기본 8장. 카드 인스턴스별로 관리하며 종류가 같아도 별개의 카드다. 카드를 사용해 슬롯이 비면 덱 선두부터 즉시 보충한다. 덱이 비면 빈 슬롯을 유지한다.
- 손패와 덱의 카드는 버릴 수 없다. 잘못 생산한 카드도 효과가 덜 유리한 상황에서 직접 사용하여 소진하는 것이 의도다. 빈 땅에 마법을 쓰는 것은 허용하되, 모험가 인구 상한 등 정상적인 사용 조건은 유지한다. 사용한 카드는 덱으로 돌아가지 않는다.
- 모험가 카드는 클릭하면 성 소환 링에 등장한다. 인구 상한이나 소환 위치 확보 실패 시 소비하지 않고 이유를 표시한다. 파티는 전체 소환 성공 또는 전체 취소로 처리한다.
- 마법 카드 클릭 → 월드 포인터에 원형 범위 미리보기 → 유효한 전장 지점 클릭으로 시전. 우클릭/Esc로 취소한다.
- UI 위 클릭은 시전으로 전달하지 않는다. 전장 밖 좌표는 무효이며 범위 일부가 경계 밖인 경우 중심점이 전장 안이면 허용한다.
- 빈 땅에도 마법을 사용할 수 있다. 공격은 적, 지원은 해당 범위의 아군만 대상으로 하며 아군 오사는 없다.
- 유효한 효과 발동이 확정된 후 1회만 소비한다. 시전 실패, 취소, 재진입 요청에서는 소비하지 않는다.
- 카드 미소모 증강은 성공적인 시전 1회에 한 번만 판정한다. 미소모여도 카드별 0.5초 재사용 잠금을 적용한다.
- 지속형 마법은 대상이 들어오고 나감에 따라 효과를 적용/해제한다. 같은 종류의 회복장은 중첩 회복하지 않고 가장 강한 것만 적용한다.
- 기존 카드에도 사용 시점의 현재 테크/증강을 반영한다. 의뢰 등록 시 저장한 비용/시간/결과 영웅은 유지하고, 카드의 전투 효과에는 사용 시점의 성장을 반영한다.

## 6. 내부 분기가 있는 6루트 테크트리

### 6.1 공통 그래프 규칙

시설 아래 루트 2개만 만들고 각각을 일직선 업그레이드로 끝내지 않는다. **각 루트에 진입 → 2개 전문화 중 선택 → 전문화 내부 2개 종결 중 선택**을 실제 노드로 만든다.

```text
시설
├─ 루트 A 진입
│  ├─ 전문화 A1 ─┬─ 종결 A1a
│  │             └─ 종결 A1b
│  └─ 전문화 A2 ─┬─ 종결 A2a
│                └─ 종결 A2b
└─ 루트 B 진입
   ├─ 전문화 B1 ─┬─ 종결 B1a
   │             └─ 종결 B1b
   └─ 전문화 B2 ─┬─ 종결 B2a
                 └─ 종결 B2b
```

- 루트당 7노드, 총 42노드. 별도 시설 공통 노드 2개씩 더해 총 48노드를 초기 데이터로 생성한다.
- 루트 진입: 시설 Lv.2 이상, 기술 포인트 1.
- 전문화: 해당 진입 노드 보유, 시설 Lv.4 이상, 기술 포인트 2.
- 종결: 해당 전문화 보유, 시설 Lv.10, 기술 포인트 3.
- 같은 루트의 두 전문화는 상호 배타적이다. 종결 노드는 **시설 전체에서 최대 1개**만 구매 가능하다.
- 다른 루트 진입과 중간 전문화는 예산 내 혼합 가능하다. 한 번의 초기 선택으로 다른 루트를 전부 닫지 않는다.
- 공통 노드 I: Lv.2/비용 1. 공통 노드 II: I 선행, Lv.5/비용 2.
- 하나의 마스터 경로는 진입 1 + 전문화 2 + 종결 3 + 공통 1 + 공통 2 = 9포인트로 완성 가능하다.
- 구매는 비용·레벨·선행·상호배타·기구매 여부를 원자적으로 검증한다. 같은 노드를 두 번 살 수 없고 MVP에서는 환불/재분배가 없다.
- 데이터는 트리만 가능한 자료형 대신 선행 ID 목록과 `All/Any` 선행 모드를 갖는 DAG로 만든다. 초기 콘텐츠에 억지로 합류 노드를 더할 필요는 없다.

### 6.2 루트 콘텐츠 기본안

아래 이름과 효과는 구현용 기본값이다. 숫자만 다른 경로 대신 공격 방식·생존 방식·대상 수·지속 효과가 달라지게 한다. 각 종결은 부모 전문화를 유지하면서 추가 효과를 준다.

| 루트 / 진입 효과 | 전문화 1 | 전문화 1의 종결 두 가지 | 전문화 2 | 전문화 2의 종결 두 가지 |
|---|---|---|---|---|
| 군-근거리 / 근접병 체력 +20% | 방패: 받는 피해 20% 감소 | **철벽:** 최대 체력 20% 보호막을 6초마다 갱신 / **반격:** 피격 시 주변 적에 공격력 40% 피해, 내부 쿨다운 1초 | 검사: 공격속도 +25% | **난격:** 세 번째 공격마다 추가 타격 1회 / **광역베기:** 기본 공격이 주변 최대 4개 적에게 60% 추가 피해 |
| 군-원거리 / 궁수 자동생산 라인 해금, 기본 6초 | 정밀: 사거리 +25% | **관통:** 화살이 최대 3개 적 관통 / **저격:** 체력 비율이 높은 적 우선, 첫 적에게 피해 +100%, 공격 간격 +30% | 속사: 공격 간격 20% 감소 | **다중사격:** 서로 다른 최대 3개 적에 60% 화살 / **폭발화살:** 명중 지점 반경 1.2에 40% 범위 피해 |
| 길드-파티 / 파티 궁수 1명을 회복 담당으로 변경 | 수호대: 파티원 근처 아군의 받는 피해 10% 감소, 같은 효과 중첩 없음 | **진형:** 파티원 2명 이상 인접 시 파티 공격속도 +25% / **구호:** 파티원 사망 시 주변 아군 최대 체력 20% 회복 | 유격대: 파티원 이동속도 +20%, 공격 간격 15% 감소 | **집중사격:** 파티가 공유 표식 대상에 피해 +35% / **연쇄토벌:** 파티 처치 시 파티 전체에 3초 가속, 최대 3중첩 |
| 길드-영웅 / 영웅 피해·체력 +20% | 결투가: 최인접 오크 우선, 단일 피해 +35% | **처형:** 보스를 제외한 적 체력 20% 이하이면 즉사, 영웅별 쿨다운 2초 / **흡혈:** 직접 피해의 10% 회복 | 전쟁영웅: 4초마다 주변 적에게 회전 공격 | **대회전:** 회전 공격 반경 +50%, 최대 대상 20 / **지휘:** 주변 군 유닛 공격속도 +25%, 중첩 없음 |
| 마법-공격 / 공격 마법 범위 +15% | 화염: 폭발 후 4초 지속 피해 지대 추가 | **업화:** 지대 체류 중 화상 최대 3중첩 / **확산:** 화상 적 사망 시 가까운 최대 2개 적에 화상 전파 | 번개: 폭발에 근처 최대 3개 적 연쇄 타격 추가 | **과충전:** 중심 반경 40% 안에 직접 피해 +100% / **연쇄폭풍:** 연쇄 대상 최대 8개, 점프마다 피해 10% 감소 |
| 마법-지원 / 지원 범위 +15% | 회복: 회복장 치유량 +30% | **보호막:** 초과 회복량을 최대 체력 20%까지 3초 보호막으로 전환 / **재생:** 범위를 떠난 뒤 3초간 기존 초당 회복의 50% 유지 | 전술장: 회복장에 아군 공격속도 +20% 추가 | **가속:** 장 안 아군 이동속도 +30%, 공격속도 효과를 +40%로 교체 / **빙결진:** 장 안 적 이동속도 30% 감소, 2초 체류 시 0.5초 기절, 적별 5초 쿨다운 |

시설 공통 노드:

| 시설 | 공통 I | 공통 II |
|---|---|---|
| 군 | 생산 간격 10% 감소 | 군 인구 상한 +40 |
| 길드 | 새 예약 생산시간 10% 감소 | 모험가 인구 상한 +6 |
| 마법 | 다음 주기부터 마법 카드 자동 지급 간격 10% 감소 | 공격/지원 마법 범위 +15% |

해석 규칙:

- 파티는 `PartyId`로 구성원을 추적하며 파티원끼리 함께 이동한다. 공통 이동 목표와 집결 범위를 사용하여 각자 다른 전선으로 흩어지지 않게 한다. 교전 시에는 근접·원거리·회복 역할에 맞는 거리를 유지하고, 교전 종료 후 다시 모여 이동한다. 집결 거리와 대형 간격은 구현용 기본값으로 둔다.
- 파티 공유 표식은 생존 중인 구성원이 공동으로 선택하며 대상 사망/이탈 시 재선정한다. 일부 파티원이 사망해도 남은 구성원은 같은 파티로 함께 이동한다.
- 루트 진입으로 파티 구성이 바뀌면 다음 소환부터 적용한다. 기존 유닛의 직업은 바꾸지 않는다.
- 유닛 통계/패시브 구매는 기존 생존 유닛과 이후 소환 유닛에 적용한다. 최대 체력 변화는 현재 체력 비율을 보존한다.
- 마법 효과는 시전 시점에 스냅샷을 만들며 이미 진행 중인 지대에는 이후 구매 효과를 소급하지 않는다.
- 지속 피해는 기본 공격으로 간주하지 않는다. 반격/폭발/연쇄 피해가 자신을 재귀 발동하지 않도록 효과 출처를 표시한다.
- 하위 전문화와 종결 선택이 툴팁뿐 아니라 전투 결과에 반영되어야 한다. 효과 처리가 없는 장식용 노드를 만들지 않는다.

## 7. 랜덤 증강

### 선택 규칙

- 사이클롭스 보스의 실제 처치 1회마다 증강 선택 기회를 1회 지급한다. 기존 2/5/8/11/14/17/20/23/26분의 시간 경과 직접 지급 규칙은 폐기한다. 보스가 등장하거나 시간이 지났다는 이유만으로 증강을 지급하지 않는다.
- 보스의 최초 사망 확정 시 고유 개체 ID+세대로 보상 중복을 막는다. 풀 반환·종료 정리·디버그 삭제는 처치 보상이 아니다. 같은 틱에 여러 보스를 처치하면 보상 기회를 순서대로 보관하고 하나씩 선택한다.
- 같은 틱에 승리/패배가 확정되면 종료 화면을 우선하고 증강 선택창을 열지 않는다. 재시작 시 미처리 보상과 보상 지급 기록을 초기화한다.
- 새 증강은 사용 가능한 풀에서 중복 없이 3개 추첨하고 1개 선택한다. 선택 중 시뮬레이션은 일시정지한다.
- 이미 획득한 비중첩 증강, 최대 스택 도달 증강, 상호배타 충돌 증강은 제외한다.
- 미투자 계열도 후보가 될 수 있어야 한다. 현재 시너지가 있는 계열 가중치를 기본 1.5배로 높이되 다른 계열의 가중치는 0으로 만들지 않는다.
- 루트 미투자 때문에 아직 효과가 약한 증강에는 활성 조건을 표시한다. 해당 루트에 이후 투자하면 활성화한다.
- 유효 후보가 3개 미만이면 있는 후보만 표시한다. 0개면 선택 창을 생략하고 다음 타이밍으로 진행한다. 무한 재추첨 루프를 만들지 않는다.
- 개발용 시드와 선택 로그를 지원한다. 증강 RNG를 스폰/전투 RNG와 분리해 전투 프레임 수가 증강 후보를 바꾸지 않게 한다.

## 8. 런 시간, 난이도, 종료

- 모든 게임플레이 타이머는 하나의 게임 시계를 사용한다. 군 생산/길드 의뢰/마법 지급/보스 출현/전투/도트/생존 시간이 서로 다른 일시정지 기준을 사용하지 않게 한다.
- 상태: `Boot → Running ↔ Paused / ChoosingAugment → Won 또는 Lost → Restart`.
- 시설/테크 팝업을 여는 것만으로는 전투를 멈추지 않는다. 사용자 일시정지와 증강 선택은 전투·생산·런 시간을 모두 멈춘다.
- 사용자 일시정지 중에는 카메라 조작, 생산 예약/취소, 시설 투자, 테크 구매, 카드 사용 등 게임플레이 조작도 받지 않고 재개 후 실행할 명령으로 쌓지 않는다. 재개·메뉴 조작은 허용한다. 증강 선택을 위한 정지에서는 해당 증강 선택만 예외로 허용하며, UI 애니메이션은 계속 가능하다.
- 일시정지 사유를 집합으로 관리한다. 증강 선택이 끝나도 사용자가 켠 일시정지는 해제하지 않는다.
- 게임플레이 한 틱의 전투 피해와 사망 처리를 마친 뒤 종료 판정한다. 같은 틱에 30분 도달과 성 파괴가 발생하면 패배 우선이다.
- 1,800초에 성이 살아 있으면 즉시 승리한다. 남은 적 전멸 조건은 없다.
- 종료 후 생산·입력·스폰·전투를 중지하고 생존 시간/처치 수/시설 레벨/구매 노드/증강을 표시한다.
- 재시작 시 모든 런 상태, 이벤트 구독, 풀 객체, 의뢰 큐, 마법 지급 상태, 보스 출현 진행 상태, 증강 보상 대기열, 덱, 손패, 시드 상태, 시간 배율을 초기화한다.

### 적 구성과 출현 기본안

확정 적은 **고블린, 오크, 사이클롭스(보스)**다. 기존 일반/고속/중장갑 3종 구성을 대체하며 별도의 고속 적은 만들지 않는다. 다음 전투 수치와 출현 비율은 잠정 구현용 기본값이다.

| 적 | 역할 | 기본 체력 | 기본 피해 | 이동속도 | 처치 보상 |
|---|---|---:|---:|---|---|
| 고블린 | 기본 물량 적 | 40 | 8 | 기준 속도 | 3G / 1XP |
| 오크 | 튼튼한 전선 압박 적 | 160 | 16 | 고블린의 65% | 10G / 4XP |
| 사이클롭스 | 보스 | 미정 | 미정 | 미정 | 증강 선택 1회, 추가 골드/XP 미정 |

- 고블린과 오크는 사방에서 성으로 진군하고 가까운 아군과 교전한다. 고블린 공격 간격은 기본 1초, 나머지 이동/공격 수치는 데이터로 조절한다. 오크에 별도 방어력이나 피해 감소는 기본 적용하지 않는다.
- 사이클롭스는 별도 보스 스폰 일정으로 생성한다. 보스 태그로 일반 적과 구분하며 즉사 효과의 대상에서 제외한다. 전용 외형·체력 표시를 제공한다. 구체적 공격 패턴과 능력치는 미정이다.
- 보스 출현 잠정안: 기존 증강 시각을 재사용하여 2/5/8/11/14/17/20/23/26분마다 사이클롭스 1마리를 출현시킨다. 이는 사용자 확정 일정이 아니며 데이터로 변경할 수 있다. 증강은 출현 시점이 아닌 실제 처치 시점에 지급한다.
- 보스를 미처치해도 일반 적 생성과 런 시간은 계속된다. 잠정안에서는 다음 보스도 예정대로 등장하므로 여러 보스가 공존할 수 있다. 30분 생존 승리 규칙은 유지하며 남은 보스 처치를 승리 조건에 추가하지 않는다.

| 시간 | 일반 적 전체 초당 생성 목표 | 잠정 구성 |
|---|---:|---|
| 0–5분 | 1 → 3 | 고블린 100% |
| 5–10분 | 3 → 6 | 고블린 85%, 오크 15% |
| 10–20분 | 6 → 15 | 고블린 80%, 오크 20% |
| 20–25분 | 15 → 25 | 고블린 75%, 오크 25% |
| 25–30분 | 25 → 40 | 고블린 70%, 오크 30% |

- 시간 구간 내부의 스폰율은 연속 보간한다. 일반 적 체력 배율은 1.0에서 3.0, 공격 배율은 1.0에서 2.0을 초기값으로 사용한다. 보스 성장은 별도 데이터로 설정한다.
- 일반 적 활성 상한 기본 1,000. 상한 도달 시 해당 틱의 일반 적 생성량을 버리고 누적 폭탄 스폰을 금지한다. 보스는 일반 적 상한과 별도로 관리하여 물량 상한 때문에 증강 획득 기회가 사라지지 않게 한다.
- 성 초기 체력 3,000, 기본 군 근접병은 체력 100/피해 12/공격 간격 1초로 시작한다. 적 구성 변경에 맞춰 골드/XP와 성장 속도를 플레이테스트로 다시 검증한다.

## 9. Unity 폴더와 씬 구성

기존 프로젝트에 동등한 구조가 있으면 기존 구조를 우선한다. 신규 프로젝트 기본안:

```text
Assets/_Game/
  Scenes/Prototype.unity
  Scripts/
    Core/             # 부트스트랩, 시계, 런 상태, RNG
    Data/             # ScriptableObject 정의, ID, 검증
    Economy/          # 골드, 처치 보상, 지휘 경험치
    Facilities/       # 시설 상태, 투자, 군 자동생산
    Production/       # 등급별 영웅/파티 의뢰와 마법 주기 지급
    Cards/            # 덱, 손패 자동 보충, 사용 검증, 타겟팅
    Combat/           # 체력, 피해, 자동 AI, 공격, 상태 효과
    Progression/      # 테크 그래프와 증강
    Spawning/         # 시간 기반 스폰
    Performance/      # 풀, 공간 그리드, 계측
    Presentation/     # 스프라이트, VFX, 오디오
    UI/               # HUD, 시설, 트리, 증강, 결과
  Editor/             # 샘플 생성, 데이터 검증 메뉴
  Data/
    Balance/ Facilities/ Units/ Cards/ TechTrees/ Augments/ Waves/
  Prefabs/
    World/ Units/ Projectiles/ Effects/ UI/
  Art/Placeholder/
  Audio/
  Tests/EditMode/
  Tests/PlayMode/
  Documentation/README.md
```

씬 루트 기본안: `GameRoot`, `World`, `Castle`, `SpawnBounds`, `PoolRoot`, `Main Camera`, `Canvas`, `EventSystem`.

- `GameRoot`에서 필요한 서비스를 명시적으로 생성/연결하고 런을 시작한다. 모든 객체를 전역 Singleton으로 만들지 않는다.
- 필요한 경우 `Tools/Game/Create Prototype` Editor 메뉴로 씬·프리팹·샘플 데이터·참조를 재현 가능하게 생성한다. 기존 사용자 에셋은 덮어쓰지 않는다.
- 생성기는 두 번 실행해도 중복 씬 객체와 데이터가 쌓이지 않게 한다. 생성 에셋 목록을 기록한다.
- UI는 기존 UI 시스템을 유지한다. 신규 프로젝트에서는 기본 Canvas UI로 충분하다. 입력은 기존 설정과 호환되게 구현하고 불필요한 입력 패키지를 추가하지 않는다.
- 런타임 어셈블리에 Editor 전용 API가 들어가지 않게 한다. 테스트 프레임워크는 설치 여부를 확인한다.

## 10. 데이터 구조

### 10.1 원칙

ScriptableObject는 읽기 전용 설계 데이터, 일반 C# 런타임 객체는 현재 플레이 상태로 분리한다. Play Mode에서 원본 에셋의 체력·큐·레벨을 수정하지 않는다. 모든 정의는 고유하고 안정적인 문자열 ID를 가지며 에셋 이름과 표시 문구를 ID로 사용하지 않는다.

| 정의 | 필수 필드 |
|---|---|
| `GameBalanceDefinition` | 런 시간, 초기 골드/성 HP, 손패/인구/큐 상한, XP 곡선, 시뮬레이션 설정 |
| `FacilityDefinition` | ID, 종류, 초기/최대 레벨, 레벨별 XP, 기본 카드 ID, 자동생산 라인, 테크 ID |
| `UnitDefinition` | ID, 진영, 역할/보스 태그, 영웅 등급(해당 시), 기본 HP/공격/간격/속도/사거리/감지 범위, 공격 패턴, 프리팹 |
| `CardDefinition` | ID, 시설, 종류, 획득 경로, 영웅 등급(해당 시), 해금 조건, 소환 구성 또는 마법 ID |
| `HeroCommissionDefinition` | 의뢰 등급 ID, 비용, 소요시간, 해금 조건, 해당 등급 영웅 후보 ID 목록 |
| `MagicSupplyDefinition` | 지급 간격, 지급 대상 카드 ID 목록, 카드 선정 방식 |
| `SpellDefinition` | ID, 대상 진영, 반경, 지속시간, 틱 간격, 효과 목록, VFX ID |
| `TechNodeDefinition` | ID, 시설/루트 ID, 필요 시설 레벨, 비용, 선행 ID 목록, All/Any 모드, 배타 그룹, 효과 목록 |
| `AugmentDefinition` | ID, 이름/설명, 태그, 기본 가중치, 최대 스택, 조건, 배타 그룹, 효과 목록 |
| `WaveDefinition` | 시작/끝 시간, 스폰율 곡선, 고블린/오크 가중치, 방향 가중치, HP/공격 배율 |
| `BossSpawnDefinition` | 출현 시각, 사이클롭스 정의 ID, 위치 규칙, 회차별 능력치 배율, 증강 보상 횟수 |
| `EffectDefinition` | 효과 종류, 대상 태그, 수치, 지속시간/쿨다운, 중첩 정책, 발동 조건 |

효과는 초기부터 임의 스크립트 실행이나 문자열 수식 엔진으로 만들지 않는다. 제한된 효과 enum/설정과 타입별 처리기를 사용하고 필요할 때 확장한다.

| 런타임 상태 | 필수 정보 |
|---|---|
| `RunState` | 런 ID, 시드, 게임 상태, 경과 시간, 골드, 지휘 XP/레벨, 투자 포인트 |
| `FacilityState` | 시설 ID, XP/레벨, 남은 기술 포인트, 구매 노드 ID, 생산 라인 타이머 |
| `ProductionOrder` | 고유 의뢰 ID, 의뢰 종류/등급, 결과 카드 ID, 지불 비용, 소요시간 스냅샷, 남은 시간, 상태, 완료 시각 |
| `MagicSupplyState` | 주기 소요시간, 남은 시간, 지급 순번, 카드 선정 상태 |
| `CardInstance` | 고유 인스턴스 ID, 정의 ID, 획득 경로, 고유 지급 ID, 생성 의뢰 ID(해당 시), 덱/손패/사용 상태, 다음 사용 가능 시각 |
| `DeckState` / `HandState` | 생산 완료 순으로 정렬된 대기 카드, 손패 슬롯, 손패 상한 |
| `UnitRuntime` | 풀 핸들+세대, 정의 ID, 소속 시설/파티, HP, 현재 대상, 공격 타이머, 버프/능력 상태 |
| `DamageContext` | 공격자/대상 핸들, 피해량, 출처 시설, 원본 효과 ID, Direct/DoT/Secondary 구분, 재귀 제한 |
| `AugmentState` | 획득 ID/스택, 보상 지급 완료 보스 핸들, 대기 중 보스 처치 보상, 현재 선택 후보 |

데이터 검증기는 중복 ID, 누락 참조, 음수 비용, 0 이하 공격/생산 간격, 잘못된 확률, 테크 순환, 다른 시설 선행 참조, 도달 불가 노드, 불가능한 포인트 비용, 연결되지 않은 카드 효과, 영웅 등급 후보 누락/등급 불일치, 0 이하 마법 지급 간격, 잘못된 보스 출현 시각을 검사한다.

능력치 계산 순서는 `기본값 → 고정 가산 → 가산 퍼센트 합 → 별도 배율 → 최소/최대 제한`으로 통일한다. 일반 버프를 영구 기본값에 반복 덧셈하지 않는다. 출처 ID로 등록/제거하고 재계산한다. 확률은 0~1, 피해 감소는 최대 80%, 공격/생산 간격은 기본 최소 0.1초로 제한한다.

## 11. 주요 시스템 책임과 연결

| `WaveDirector` | 고블린/오크 물량과 상한, 별도 사이클롭스 출현 일정 | 시간 경과만으로 증강 지급/승리 시간 연장 |

사망 처리 순서: 피해 확정 → 생존 특수능력 확인 → 최초 사망 확정 → 사망 효과/보상 1회 → 활성 목록/인구/그리드 제거 → 표현 정리와 풀 반환. 종료 정리용 강제 반환에는 처치 보상을 주지 않는다.

한 틱의 기본 흐름: 명령 처리 → 생산/스폰 → 이동 및 그리드 갱신 → 표적 탐색/공격·효과 → 사망/보상 → 레벨/증강 이벤트 정리 → 승패 판정 → UI/VFX 이벤트 전달. 컬렉션 순회 중 생성/삭제는 별도 버퍼로 모아 안전한 시점에 반영한다.

## 12. UI와 피드백

- 상단: 성 HP, 생존 시간/30:00, 골드, 지휘 XP/레벨, 미사용 투자 포인트, 일시정지.
- 모든 사용자 대상 UI는 한국어로 표시한다.
- 성 확대 시 군·길드·마법 시설이 구별되어 보이고, 각 시설 더블클릭으로 해당 테크트리 팝업을 연다. 팝업에는 시설 레벨/XP/기술 포인트와 투자 버튼을 함께 표시한다.
- 군 패널: 근접병/궁수의 해금 상태, 라인별 다음 자동생산까지의 진행률, 현재/최대 인구. 생산 예약이나 수동 출격 버튼은 없음.
- 길드 패널: 영웅 등급별 후보 정보·비용·소요시간·의뢰 버튼, 파티 의뢰, 의뢰 큐 순서·남은 시간·취소 가능 여부.
- 마법 패널: 자동 지급 주기·다음 지급까지 남은 시간·지급 대상 카드 설명. 생산 예약/결제 버튼은 없음.
- 사이클롭스 보스의 체력과 출현을 별도로 표시하고, 처치 후 증강 선택 보상임을 안내한다.
- 하단: 손패 8슬롯과 덱의 대기 카드 수. 손패로 들어오는 카드에는 짧은 강조 효과를 준다. 손패가 가득 차면 완성 카드가 덱에 보관됨을 표시한다. 카드 버리기/판매 버튼은 제공하지 않는다.
- 테크 화면: 연결선, 조건, 비용, 효과, 구매됨/구매 가능/잠김/배타 잠김을 색과 문구로 구분.
- 증강 화면: 3개 선택지, 현재 빌드와 관련된 태그, 효과와 조건. 선택 후 정확히 한 번 닫힘.
- 마법 미리보기: 공격/지원 색을 구분하고 유효/무효 좌표를 시각화한다.
- 공격 히트/광역 폭발/치유/유닛 사망은 별도 표현을 사용한다. 적과 아군 실루엣/색을 구분한다.
- VFX가 늘어도 성 체력, 적 접근, 마법 범위가 가려지지 않게 한다. 피해 숫자는 기본 비활성 또는 집계형으로 둔다.
- 재사용 가능한 설명 문구로 골드 부족, 큐 가득 참, 손패 가득 참, 인구 부족, 선행 노드 부족을 표시한다.

## 13. 성능과 풀링 지침

### 목표와 측정

프로토타입 목표는 기준 PC 또는 Mac의 1080p Standalone에서 적 1,000 + 군 120 + 모험가 18 + 투사체 300 + 효과 100이 있는 스트레스 장면에서 60 FPS에 접근하는 것이다. 이는 **검증할 목표이며 보장된 결과가 아니다**. 실제 측정 기기/해상도/빌드 종류/활성 개체 수를 함께 기록한다.

- 초기 워밍업 후 120초 측정: 평균 FPS와 프레임 시간 p95, 메인 스레드/렌더 병목, GC 할당, 풀 확장/누락, 활성 개체 수.
- 전투 핵심 반복 구간은 워밍업 후 프레임당 관리 힙 할당 0B를 목표로 한다. UI 갱신/풀 확장과 구분하여 측정한다.
- 25~30분 실제 플레이의 부하와 인위적 최대 개체 스트레스를 각각 확인한다. Editor 수치를 Standalone 결과처럼 보고하지 않는다.

### 구현 규칙

1. 적/군/모험가/투사체/피격 효과/지속 마법/부동 텍스트는 풀링한다. 핫패스 `Instantiate/Destroy` 반복을 피한다.
2. 반환 시 HP, 타겟, 파티 ID, 버프, 쿨다운, 부활 사용 여부, 타이머, 이벤트 구독, Trail/Particle 상태를 초기화한다.
3. 풀 재사용 참조에는 ID+세대 번호를 사용한다. 오래된 투사체가 반환 후 재사용된 다른 유닛을 맞히지 않게 한다.
4. 유닛마다 매 프레임 모든 적을 검색하지 않는다. 균일 공간 그리드/공간 해시로 주변 셀만 조회한다.
5. AI 표적 재탐색은 0.1~0.2초 간격으로 분산한다. 이동/표현은 필요한 주기로 갱신한다. 그리드는 이동 후 갱신하여 빠른 적을 놓치지 않게 한다.
6. LINQ, 람다 임시 할당, 매 프레임 문자열 보간, 전역 객체 검색, 반복 GetComponent를 전투 루프에서 피한다. 버퍼와 컴포넌트 참조를 재사용한다.
7. 강체 수천 개로 서로 밀어내지 않는다. 장애물 없는 이동+근처 소수 대상 분리로 시작한다. 실제 충돌은 필요한 레이어에만 둔다.
8. 투사체는 이전 위치부터 현재 위치까지의 선분 판정 등으로 고속 관통 누락을 막는다. 관통/튕김의 이미 맞힌 대상 목록은 재사용 버퍼로 관리한다.
9. 범위 판정 버퍼가 넘치면 분할 처리/확장 등으로 정확도를 유지한다. 단지 버퍼가 작다는 이유로 범위 안 적을 조용히 누락하지 않는다. 게임 규칙의 최대 타깃 수는 별도로 명시한다.
10. VFX/오디오/피해 숫자는 표현 예산을 초과하면 축약할 수 있다. 표현을 생략해도 피해/치유/보상은 동일해야 한다.
11. 실제 투사체 풀이 부족하면 제한 내 확장 또는 동일 판정의 논리 투사체 대체를 사용한다. 공격만 소모하고 피해가 사라지는 구현을 금지한다.
12. 스프라이트 공용 머티리얼, 과도한 투명 오버드로 제한, 파티클 수명/개수 제한을 적용한다. 스프라이트별 독립 머티리얼 생성은 피한다.
13. UI 숫자는 변경 시 또는 낮은 주기로 갱신한다. 대량 체력바와 이름표를 기본 생성하지 않는다.
14. 처음부터 ECS/DOTS 전환을 전제로 만들지 않는다. 중앙 갱신·풀링·공간 조회를 먼저 구현하고 프로파일러 근거로 병목을 개선한다.

## 14. 구현 우선순위와 구체적인 작업 순서

각 단계를 완료하고 검증한 뒤 다음으로 진행한다. 모든 아키텍처를 먼저 빈 코드로 생성하지 말고 작동하는 범위를 순차적으로 넓힌다.

### 단계 0 — 프로젝트 조사와 실행 기반 (P0)

- 버전/패키지/기존 변경을 확인하고 충돌 없이 작업 영역을 만든다.
- 부트스트랩, 런 상태, 게임 시계, 데이터 ID/검증, 샘플 생성 진입점을 작성한다.
- 임시 성/유닛/카드 UI에 필요한 도형 에셋과 씬을 준비한다.
- **통과:** 씬을 열어 Play하면 카메라/HUD/성이 보이며 콘솔 컴파일 오류가 없다.

### 단계 1 — 자동전투 수직 슬라이스 (P0)

- 풀과 활성 개체 목록, 공간 그리드, 일반 적 스폰, 기본 근접병 자동생산, 이동/공격/성 피해/사망을 연결한다.
- 골드/경험치 보상과 3분 디버그 런, 패배/재시작을 연결한다.
- **통과:** 조작 없이 군과 적이 싸우고 적 사망 보상이 1회만 지급되며 성이 파괴될 수 있다.

### 단계 2 — 유료 생산과 카드 조작 (P0)

- 길드 등급별 영웅/파티 의뢰와 결제/취소, 마법 무료 주기 지급, 공용 덱, 손패 자동 보충, 기본 모험가와 공격/지원 카드 구현.
- 마법 범위 미리보기/취소/UI 입력 차단, 모험가 자동 소환을 연결한다.
- **통과:** 영웅 의뢰 완료 시 해당 등급 카드가 나오고 마법은 예약/결제 없이 주기마다 1장 지급된다. 가득 찬 손패/인구 제한에서도 손실이나 중복이 없다.

### 단계 3 — 시설 성장과 여섯 루트 (P1)

- 지휘 XP → 투자 → 시설 XP/레벨 → 기술 포인트 흐름을 구현한다.
- 테크 DAG 구매 검증과 UI를 만든다. 48노드 데이터를 생성한다.
- 군 원거리, 파티/영웅 차별화, 공격/지원 내부 전문화와 종결 효과를 구현한다.
- **통과:** 여섯 루트 각각의 두 전문화와 네 종결을 디버그로 선택해 효과를 확인한다. 단일 런에서 모든 종결을 동시에 획득할 수 없어야 한다.

### 단계 4 — 증강과 빌드 조합 (P1)

- 별도 시드 추첨, 사이클롭스 처치 보상 트리거, 선택 일시정지, 12종 효과를 연결한다.
- 증강/테크의 출처별 능력치와 이벤트 처리, 재귀 방지, 동시 처치 보상을 검증한다.
- **통과:** 같은 시드/진행 조건에서 같은 후보가 나오고, 기존 빌드 강화와 새 계열 유도가 모두 가능하다.

### 단계 5 — 30분 구성과 후반 연출 (P1)

- 정식 1,800초 모드, 고블린/오크 물량 곡선과 사이클롭스 보스 일정, 후반 물량, 결과 화면을 완성한다.
- 군 근접/원거리/길드 파티/길드 영웅/공격 마법/지원 중심 분배를 각각 시험한다.
- **통과:** 정상 경로로 30분 승리와 성 파괴 패배, 재시작을 확인하고 후반 전투가 초반보다 명확히 커진다.

### 단계 6 — 성능·회귀 검증과 인계 (P1)

- 부하 프리셋, 프로파일링, 풀 확장/GC/탐색 병목 개선.
- EditMode/PlayMode 테스트와 플레이 체크리스트 수행.
- README에 씬/빌드 실행, 디버그 메뉴, 밸런스 데이터 위치, 실제 검증 결과를 기록한다.
- **통과:** 15절 체크를 만족하거나 미완료와 실제 원인을 구체적으로 보고한다. 더미 동작이나 미연결 데이터로 완료를 선언하지 않는다.

## 15. 검증 계획과 수락 기준

### EditMode 핵심 테스트

- 수동 예약 없이 근접병이 주기적으로 생산됨. 원거리 해금 전 궁수 생산 없음, 해금 후 첫 주기부터 궁수 생산과 근접병 생산이 독립적으로 지속됨.
- 군 인구 상한에서 완료 생산 대기, 슬롯 반환 시 1회 보충, 대기 시간에 비례한 병력 몰아 생성 없음. 일시정지 중 두 생산 타이머 정지.

- 길드 의뢰에서 돈 부족/큐 가득 참/등급 후보 없음이면 지출 0, 성공 의뢰에서 정확한 1회 차감. 등록 등급과 지급 영웅 등급 일치, 완료 카드 중복 지급 없음.
- 마법은 골드/의뢰 없이 주기당 정확히 1장 지급, 손패 포화 시 덱 적재와 지급 지속, 일시정지 중 타이머 정지, 재시작 시 초기화.
- 대기 주문 취소 전액 환불, 진행/완료 주문 취소 불가, 이중 취소 방지.
- 손패 포화 시 완료 카드의 덱 적재와 후속 생산 지속, 슬롯 해제 후 FIFO 순서로 정확히 1회 보충. 동시 생산 완료 순서와 덱이 빈 경우 검증.
- 손패/덱 카드 버리기·판매·환불 불가, 사용한 카드의 덱 재진입 없음.
- 한 번의 XP 보상으로 다중 레벨업, 초과 XP 이월, 지휘/시설 만렙에서 잘못된 포인트 증가 없음.
- 투자 포인트와 기술 포인트 중복 사용 불가, 최대 예산 15, 10/6/2 가능, 두 시설 만렙 불가.
- 순환/누락/불가능한 테크 데이터 탐지, 전문화 배타, 시설 종결 1개, 모든 루트의 종결 도달 가능.
- 증강 중복/스택/후보 부족, 고정 시드, 선택 이중 처리 방지. 시간 경과/보스 등장만으로 증강이 뜨지 않고 보스 실제 처치당 보상 1회.
- 보스 동시 처치 보상을 순차 처리하고, 풀 반환/종료 정리에서 보상 없음. 승패 확정 시 증강 창이 종료 화면을 가리지 않으며 재시작 후 보상이 이월되지 않음.
- 같은 적의 동시 피해/도트 사망에서 보상 1회, 부활한 영웅의 슬롯 유지.
- 버프 제거 후 원래 능력치 복원, 파생 피해의 재귀 발동 차단.
- 30분과 성 사망이 같은 틱이면 패배, 일시정지 중 게임플레이 시간과 조작 정지. 정지 중 명령이 재개 후 실행되지 않으며 증강 선택만 해당 정지에서 예외로 허용됨.

### PlayMode와 수동 확인

- 사방 적 생성 → 군 자동생산 → 교전 → 보상 → 생산 → 카드 → 성장 → 승패까지 실제 씬에서 연결됨.
- 모험가 카드를 사용하면 방향 입력 없이 성에서 출격하여 자동전투함.
- 공격/지원 범위 미리보기와 실제 대상 판정 일치, UI 클릭·취소·전장 밖 클릭 시 카드 보존.
- 파티 슬롯 부족에서 일부만 소환되는 문제가 없음.
- 손패 8장과 길드 의뢰 완료/마법 주기 지급 카드를 덱에 쌓은 뒤 한 슬롯씩 비워 순서 보존과 누락/복제 없음 확인. 손패가 가득 차도 의뢰와 자동 지급은 계속됨.
- 고블린/오크 일반 물량과 별도 사이클롭스 출현, 보스 처치 → 증강 선택 → 전투 재개를 확인한다. 보스가 즉사 효과의 대상이 되지 않음.
- 휠 확대·축소, WASD/좌클릭 드래그 이동, 성 확대 시 시설 표시, 시설 더블클릭 테크 팝업과 한국어 UI 확인. 드래그 종료가 클릭/마법 시전으로 오인되지 않음.
- 파티가 함께 이동하고 역할별 교전 거리를 유지하며, 일부 사망/표적 변경 후에도 흩어지지 않음.
- 6루트 × 4종결의 효과를 개별 시나리오로 확인하고 두 전문화가 서로 다른 전투 결과를 내는지 기록.
- 카드 미소모 + 연속 주문, 광역베기 + 추가 공격, 파티 분산 피해 + 사망 효과의 상호작용 확인.
- 풀 반환/재사용 뒤 낡은 타겟·파티·버프·부활 상태가 이어지지 않음.
- 3회 연속 재시작해 이벤트/카드/보상/생산 속도가 중복되지 않음.
- 정상 30분 런, 25분 부하 프리셋, 최대 개체 스트레스 결과를 구분해 기록.

### 디버그 도구

개발 빌드/Editor에서만 골드·XP 지급, 시설 투자/노드 선택, 증강 지정, 시드 표시, 시간 배율, 적 스폰, 풀/개체/GC 표시를 제공한다. 후반 프리셋은 시계만 25분으로 옮기지 말고 명시된 시설/카드/적 상태를 함께 구성한다. 시간 배율/프리셋 검증은 실제 1배속 30분 생존 확인을 대체하지 않는다.

## 16. 최종 제출물

1. 실행 가능한 `Prototype` 씬 또는 기존 프로젝트의 대응 씬.
2. 연결된 프리팹·ScriptableObject 데이터·UI·임시 그래픽.
3. 군 자동생산, 카드 생산/사용, 자동전투, 시설 성장, 6루트 내부 분기, 증강, 30분 런 구현.
4. 데이터 검증과 핵심 테스트, 재현 가능한 디버그/부하 프리셋.
5. `Assets/_Game/Documentation/README.md`: 사용 Unity 버전, 실행 방법, 조작, 데이터 수정 위치, 구현 기본값, 테스트/성능 결과, 알려진 문제.
6. 사용자에게 전달할 짧은 완료 보고: 무엇을 구현했고 어떻게 확인했는지, 미실행 검증과 남은 작업이 있는지.
